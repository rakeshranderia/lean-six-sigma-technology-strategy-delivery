# v1.0.0 — Stable Reference

This release consolidates the remaining planned layers of **Lean Six Sigma for Technology Strategy & Delivery** into the first stable reference version.

Rather than publish several small releases in quick succession, v1.0.0 brings the portfolio, program, benefits and practical-tool layers together for review as one coherent framework.

## Added

### Technology Tool Crosswalk
Maps Voice of Customer, CTQ, SIPOC, process/value-stream mapping, Pareto, 5 Whys, fishbone, FMEA, Cost of Poor Quality, control plans, mistake-proofing and related tools to technology use cases.

### Portfolio Prioritisation
Adds:
**Demand → Define → Measure → Analyse → Prioritise → Fund/Defer/Stop → Deliver → Measure Benefits → Rebalance**

### Program Benefits Mapping
Adds:
**Project Output → Capability Change → Behaviour / Process Change → Outcome → Benefit**

Core principle:
> Five green projects do not guarantee a successful program.

### Benefits Realisation & Control Loop
Adds:
**Deliver → Operate → Measure → Compare to Baseline → Learn / Adjust → Feed Strategy & Portfolio**

### Additional Worked Example
Adds a service-desk flow-improvement example showing how evidence can reveal waiting, approval design and ownership as larger contributors than active handling time.

### Static Interactive Tool
Adds a deployable **Technology Roadmap Evidence Check** under `tools/`.

## Stable framework scope
The framework now spans:

**Business Need → Strategy → Roadmap → Portfolio → Program → Project → Operations → Benefits**

with DMAIC as the horizontal evidence discipline:

**Define → Measure → Analyse → Improve → Control**

## Positioning
Lean Six Sigma is presented as a complementary decision and improvement discipline. It does not replace established strategy, architecture, portfolio, program, project, Agile, product or service-management practices.

## Next step
No immediate follow-on release is planned. The framework should now be reviewed and allowed to evolve from practical use, feedback and real examples.
