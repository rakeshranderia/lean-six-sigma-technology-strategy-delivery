# 15. Worked Example: Service Desk Flow Improvement

> **Note:** This example is illustrative and uses fictional figures.

A service desk meets its formal SLA but users report that standard requests feel slow and require repeated follow-up.

The initial proposal is:

> Implement more service-desk automation.

The Lean Six Sigma lens starts with the process.

## DEFINE

Problem statement:

> Standard access and service requests take too long end-to-end, despite acceptable handling time once work begins.

Desired outcomes:

- reduce elapsed fulfilment time;
- reduce avoidable hand-offs;
- improve user visibility;
- preserve security and approval quality.

## MEASURE

| Measure | Baseline |
|---|---:|
| Average end-to-end fulfilment time | 3.8 days |
| Average active handling time | 42 minutes |
| Average queue/waiting time | 3.1 days |
| Average hand-offs | 4.2 |
| Requests returned for missing information | 17% |
| First-contact resolution for eligible requests | 39% |
| Requests requiring manual approval | 78% |

The key observation is:

> Active handling time is not the dominant issue. Waiting is.

## ANALYSE

A value-stream review identifies:

- manager approval queue;
- incomplete request information;
- repeated identity verification;
- specialist assignment for low-risk tasks;
- unclear ownership between service desk and application teams.

A Pareto view shows that three request types account for most volume.

The problem is not primarily lack of service-desk staff.

## IMPROVE

### Better request capture
- dynamic forms;
- mandatory context;
- role-based options.

### Risk-based approval
- low-risk standard requests pre-approved by policy;
- exceptions retain manual approval.

### Automation
- identity and group changes automated where rules are deterministic.

### Ownership
- standard service owner defined;
- selected application-team hand-offs removed.

### User visibility
- status and expected timing surfaced automatically.

Delivery can occur iteratively.

## CONTROL

| Measure | Owner | Frequency | Threshold |
|---|---|---|---|
| End-to-end fulfilment time | Service owner | Weekly | > target |
| Queue time | Service desk | Weekly | > target |
| Returned requests | Process owner | Monthly | > 8% |
| Automation success | Platform owner | Weekly | < 98% |
| Security exceptions | Security | Monthly | risk-based threshold |

## BENEFITS

Illustrative six-month outcome:

- fulfilment time reduced from 3.8 days to 1.1 days;
- fewer hand-offs;
- fewer returned requests;
- lower manual approval for standard low-risk requests;
- specialist effort redirected to higher-value work.

The lesson is:

> The proposed solution — “more automation” — was only one part of the improvement.

Measurement showed that waiting, approval design and ownership were larger contributors than active handling time.
